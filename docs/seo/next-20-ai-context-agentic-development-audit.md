# Next 20: AI Context and Agentic Development — Content Audit

Audited 2026-10-08 against all 804 published articles, dumped from `src/lib/blog-data*.ts` (posts render through `src/app/blogs/[slug]/page.tsx`; sitemap from `src/app/sitemap.ts`; BlogPosting, BreadcrumbList and FAQPage schema come from the shared template). Each proposal was compared by exact URL, title, H1, section headings, body text (full-text search for the defining terms) and search intent.

**Method notes**

- Full-text term counts across the corpus before writing: "semantic layer" 0, "ontology" 0, "software factory" 0, "worktree" 0, "agentic QA" 0, "data product" 1, "entity resolution" 5 (passing mentions in commerce/AI articles), "data contract" 11 (two sections in pipeline articles), "provenance" 32 (mostly supply-chain and lineage mentions), "freshness" 104 (spread across RAG, real-time and commerce feed articles).
- No keyword-volume tool (DataForSEO, Semrush, Ahrefs, Google Ads) is configured for this project, so **no search volumes or difficulty scores are given**. Intent was judged from the query wording, current vendor and documentation terminology, and the type of pages that answer each query today.

**Outcome:** 4 GREEN, 12 YELLOW, 4 RED. **18 articles to publish** (16 proposals plus 2 replacements). The 4 RED intents are served by extending the existing owner URL instead.

## Why the RED decisions

- **#10** would repeat the existing article's definition, context types, long-task techniques and memory guidance under a near-identical query. Extending the existing URL keeps one strong page for "context engineering" and lets the new architecture link down to the new data articles.
- **#11** is the transition the modes comparison already describes (assistant → agent → agentic), and the SDLC article already walks requirements to monitoring. A third page would compete with both. The transition table and "what humans keep" go into the comparison article.
- **#19** and **#20** are the same intents as articles published on 2026-10-08 (same day). Both are extended.

## Cannibalization watch-list inside the new set

| Pair | Risk | Differentiation |
|---|---|---|
| Business context layer vs semantic layer vs ontology | Medium | Context layer = umbrella architecture (definitions, rules, entities, permissions, time, org) for documents and data. Semantic layer = metrics and dimensions over structured data. Ontology = the conceptual model of entities and relationships. Each article states the relationship explicitly. |
| Semantic layer vs text-to-SQL | Low–medium | Semantic layer = what it is; text-to-SQL = the query technique, its failure modes and the options (raw schema, curated views, semantic layer). |
| Data freshness vs real-time data for AI | Medium | Freshness = requirements, staleness controls, TTLs and decisions; real-time = building streaming pipelines. |
| Data provenance vs AI data lineage | Medium | Provenance = per-answer evidence chain; lineage = dataset and pipeline graph. |
| Parallel agents vs agents + Git | Medium | Parallel = decomposition, isolation, coordination; Git = branch, commit, PR, merge and rollback conventions. |
| Code provenance vs agents + Git | Low | Provenance = recording AI involvement for audit; Git workflow = how work moves. Git article links to provenance for trailers. |
| AI code tech debt vs AI automation tech debt | Low | Code maintainability vs workflow/prompt debt. Cross-linked. |
